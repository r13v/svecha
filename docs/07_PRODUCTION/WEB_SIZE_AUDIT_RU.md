# Размер браузерной сборки — аудит 13 сентября 2026

**Обновление:** первый проход оптимизации реализован; новая локальная сборка передаёт 49,92 МиБ с gzip. [Изменения, проверка и сравнение кадров](../04_BLENDER_ENV/fidelity/web_size/README_RU.md). Ниже сохранены исходные измерения и предложения на момент аудита.

Запрос: значительно сократить ожидание первой загрузки; допустимы радикальные изменения. Выполнен аудит существующей сборки, оптимизация и публикация не выполнялись. Локальная Web-сборка ещё не содержит кота.

## Измерено

Разобран каталог `builds/web/index.pck`; размеры и содержимое всех 545 файлов проверены по MD5 из PCK. Дубликаты найдены по SHA-256 содержимого. МиБ = 1 048 576 байт.

| Содержимое | МиБ до HTTP-сжатия |
| --- | ---: |
| Текстуры | 134,87 |
| Модели и отдельная геометрия для запечённого света | 40,33 |
| Карта запечённого света | 8,00 |
| Прочее, включая звук и скрипты | 0,46 |
| **Всего PCK** | **183,72** |
| Движок WASM | 37,68 |

В текстурах **58,67 МиБ побайтовых дубликатов сверх одной необходимой копии**. Например, одинаковая normal map дерева лежит в десяти файлах и занимает лишние 12 МиБ. Это измеренный резерв содержимого PCK, а не гарантированное сокращение сетевой передачи на ту же величину. Для его реализации нужны общие ресурсы и исправленные ссылки, простое удаление файлов сломает модели.

В копии Web-проекта 96 текстур импортируются с VRAM-сжатием, 69 — без потерь. Одинаковые исходные изображения местами имеют разные настройки сжатия. Размер обычных текстур уже ограничен 1024; карты света обрабатываются отдельно. Экспорт включает все ресурсы; модели, звук и геометрия света загружаются также по вычисляемым путям, поэтому переход на экспорт только зависимостей сцены требует явного учёта этих файлов.

Проверка HEAD публичных `index.pck` и `index.wasm` с `Accept-Encoding: gzip, br` показала HTTP 200 и `Content-Encoding: gzip`. Content-Length: 160 650 520 и 10 248 949 байт соответственно — **162,98 МиБ передачи** для двух основных файлов. На канале 20 Мбит/с это теоретически около 68 секунд только передачи; загрузка из конкретного браузера и время запуска не измерялись. Размеры несжатых публичных файлов в ETag совпадают с локальными.

## Предлагаемый порядок

1. Общие текстуры вместо копий; исключить действительно неиспользуемые ресурсы с учётом динамических загрузок. Внешний вид должен сохраниться.
2. Отдельный профиль Web: 512 пикселей для фоновых материалов, 1024 для важных близких предметов и икон. Сравнить Lossy и Basis Universal для подходящих карт; проверить качество normal maps, время декодирования и расход видеопамяти в браузере. Потери не складываются арифметически с экономией от устранения дубликатов.
3. Упростить тяжёлую геометрию крыши, дерева и геометрию для lightmap. Перезапечь свет после изменения соответствующих моделей. Не удалять запечённое освещение вслепую: для Web уже открыта проблема скачков динамических теней.
4. После уменьшения ресурсов рассмотреть собственный минимальный шаблон Godot и Brotli. Gzip уже включён; его повторное включение ничего не даст. Кэш ускорит повторные открытия, но не первую загрузку.

Рабочая цель после оптимизации в Godot — **30–50 МиБ сетевой передачи** с сохранением маршрута и свободного движения. Это бюджет для проверки, не результат сборки и не обещание. Критерии: повторный замер опубликованных файлов, холодная загрузка до управляемой сцены, проход всего эпизода, сравнение двери, интерьера, руки и свечи из камеры игрока.

Радикальные варианты: стилизация с небольшим набором общих материалов и сокращённой детализацией; перенос на браузерный 3D-движок с переписыванием логики; переход к заранее отрисованным ракурсам с отказом от свободной ходьбы. Выбор художественного направления пока не сделан. Догрузка интерьера может сократить стартовое ожидание, но сохраняет общий объём и требует проверки отсутствия остановки у двери.
