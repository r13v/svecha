# Браузерная версия

Целевая платформа — браузер на компьютере с клавиатурой и мышью. Управление: WASD, мышь, E, Esc. Сенсорное управление пока не добавлено.

## Сборка

Нужны Godot 4.7.2 stable, его шаблоны Web, Python 3 и rsync.

```sh
./tools/export_web.sh
python3 -m http.server 8787 --bind 127.0.0.1 --directory builds/web
```

Открыть [локальную игру](http://127.0.0.1:8787). Прямое открытие `index.html` с диска не запускает WebAssembly.

Скрипт готовит `.tools/web-project/`, ограничивает импорт обычных текстур до 1024 пикселей и экспортирует `builds/web/index.html`. Исходные модели, текстуры и настройки их импорта сохраняются в `game/`. Запечённые карты света сохраняют исходное разрешение.

Web использует Compatibility / WebGL 2.0 и один поток. Специальные заголовки COOP/COEP и service worker не требуются. Объёмный туман и подповерхностное рассеяние кожи доступны в Forward+; в браузере они отключены. Запечённое освещение, геометрия и игровой сценарий используются общие. «В главное меню» перезапускает эпизод внутри вкладки.

## GitHub Pages

Workflow `.github/workflows/pages.yml` собирает игру на Godot 4.7.2, проверяет игровой маршрут и публикует только `builds/web`. Он запускается при изменениях игры в `main` или вручную через Actions → «Опубликовать игру» → Run workflow.

Источник публикации в Settings → Pages должен быть **GitHub Actions**. Скомпилированные `.pck` и `.wasm` передаются как артефакт Pages и не добавляются в историю Git.

## Проверка

Проверка скриптов и автоматический игровой маршрут выполняются отдельно от браузерного запуска. Загрузка страницы, изображение, захват мыши, пауза и прохождение требуют проверки браузера. Результат первой публикации будет записан после проверки.

Официальные ограничения: [экспорт Godot для Web](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html), [workflow GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
