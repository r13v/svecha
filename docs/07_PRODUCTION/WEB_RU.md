# Браузерная версия

[Играть в «Свечу»](https://r13v.github.io/svecha/). Обновлено 14 сентября 2026 года; [успешная сборка и публикация](https://github.com/r13v/svecha/actions/runs/34819663585), игровой коммит `e8ab4d5`. Опубликованы новые шаги и дверь, экран загрузки и атрибуция elevenlabs.io.

Публичные HTML, PCK, WASM и титры возвращают HTTP 200. Дверь и оба выбранных шага в загруженном с сайта PCK побайтно совпадают с локальной сборкой; дублей 02 и 04 нет. Игра запущена в Chromium без ошибок в журнале: [кадр сайта](../04_BLENDER_ENV/fidelity/audio/published_page.png), [контрольные суммы и результат проверки](../04_BLENDER_ENV/fidelity/audio/published_verification.json). При первом открытии загрузка превысила минуту; повторное ожидание завершилось успешно.

Целевая платформа — браузер на компьютере с клавиатурой и мышью. Управление: WASD, мышь, E, Esc. Сенсорное управление пока не добавлено.

## Сборка

Нужны Godot 4.7.2 stable, его шаблоны Web, Python 3 и rsync.

```sh
./tools/export_web.sh
python3 -m http.server 8787 --bind 127.0.0.1 --directory builds/web
```

Открыть [локальную игру](http://127.0.0.1:8787). Прямое открытие `index.html` с диска не запускает WebAssembly.

Скрипт готовит `.tools/web-project/` и экспортирует `builds/web/index.html`. Web-профиль ограничивает фоновые текстуры до 512 пикселей, иконы и текстуру кожи руки — до 1024; цвет и шероховатость используют Lossy WebP, normal maps — VRAM-сжатие. Исходные модели, текстуры и настройки их импорта сохраняются в `game/`. Запечённые карты света сохраняют исходное разрешение.

После экспорта одинаковые данные ресурсов хранятся в PCK один раз при сохранении всех путей. Упаковщик проверяет целостность содержимого и обновляет размер в HTML. Отчёт — `.tools/checks/web-size.json`; превышение бюджета 50 МиБ с gzip, уровень 6, останавливает сборку. [Результат и сравнение кадров](../04_BLENDER_ENV/fidelity/web_size/README_RU.md): локальная сборка уменьшена с 164,95 до 49,92 МиБ передачи. Оптимизация опубликована; текущая сборка со звуками занимает около 49,95 МиБ с gzip.

Web использует Compatibility / WebGL 2.0 и один поток. Специальные заголовки COOP/COEP и service worker не требуются. Объёмный туман и подповерхностное рассеяние кожи доступны в Forward+; в браузере они отключены. Запечённое освещение, геометрия и игровой сценарий используются общие. «В главное меню» перезапускает эпизод внутри вкладки.

В локальной сборке исправлены засветки архитектуры при исчезновении динамических теней: к LightmapGI добавлена запечённая маска Shadowmask Overlay. Дверь и свечи остаются динамическими. Маска экспортируется без RGTC-сжатия и без уменьшения разрешения. [Кадры, проверка и сравнение производительности](../04_BLENDER_ENV/fidelity/web_lighting/README_RU.md). Обновление включено в опубликованную сборку GitHub Pages.

## Экран загрузки

В опубликованной сборке стандартная заставка заменена на [шаблон «Свечи»](../../game/web/loading.html): тёмный оливковый фон, восковая свеча, мягкое движение пламени и название игры. SVG нарисован для проекта; внешние изображения, шрифты и библиотеки не загружаются. Настройка `html/custom_html_shell` сохраняет оформление при каждом экспорте; стандартное изображение загрузки движка отключено только для Web.

Процент отражает получение ресурсов через `onProgress`, после получения всех байтов надпись меняется на «Входим в храм…». Загрузчик исчезает после завершения `startGame`. При неизвестном размере показывается индикатор без процента; при ошибке есть русское сообщение, технические подробности и кнопка повторной попытки. Предпочтение уменьшенного движения отключает анимацию пламени.

[Кадр реальной загрузки](../04_BLENDER_ENV/fidelity/loading/web_loading.png) · [Узкий экран, проверочный прогресс 37%](../04_BLENDER_ENV/fidelity/loading/narrow.png). Проверены размеры 1600×900, 640×360 и 390×844; узкое оформление не добавляет сенсорное управление игрой. Экран загрузки опубликован на GitHub Pages.

## GitHub Pages

Workflow `.github/workflows/pages.yml` собирает игру на Godot 4.7.2, проверяет игровой маршрут и загрузку WebGL без ошибок, затем публикует только `builds/web`. Он запускается при изменениях игры в `main` или вручную через Actions → «Опубликовать игру» → Run workflow.

Источник публикации в Settings → Pages должен быть **GitHub Actions**. Скомпилированные `.pck` и `.wasm` передаются как артефакт Pages и не добавляются в историю Git.

## Проверка

Проверка скриптов и автоматический игровой маршрут выполняются отдельно от браузерного запуска. CI запускает `python3 tools/test_web_export.py`, проверку бюджета размера и игровой маршрут на конечном PCK. Для проверки загрузки движка и отсутствия ошибок используется программный SwiftShader через `./tools/check_web.sh --load-only`. Это не проверка производительности на видеокарте. Если загрузка на программном рендеринге превышает внутренний тайм-аут CDP, ожидание повторяется один раз. Постоянное зависание и ошибки браузера по-прежнему останавливают публикацию.

`./tools/check_web.sh` без параметров также проверяет захват мыши, движение и паузу и сохраняет кадры. Нужен установленный `agent-browser` 0.37.1 и разблокированный рабочий стол. Первая локальная проверка показала меню и изображение WebGL, но захват мыши был заблокирован вместе с Mac; полная проверка управления остаётся открытой.

После Web-экспорта `python3 tools/check_web_lighting.py` проверяет маску на реальных ресурсах PCK в WebGL: потерю динамической тени, сохранение оконного света, открытие двери и маршрут камеры. Флаг `--baseline` отключает маску только в тесте; контрольный прогон должен завершиться с ошибкой проверки. Результаты и кадры — `.tools/checks/web-lighting/`.

Проверено: импорт и экспорт, проверка скриптов, `CANDLE_ASSET_CHECK: PASS`, `GAME_CHECK: PASS`, загрузка WebGL в Chromium без ошибок, успешный deploy Pages, HTTP 200 для HTML/PCK/WASM и `application/wasm` для движка. Сервер отдаёт ресурсы с gzip. Размер до HTTP-сжатия — около 59,71 МиБ PCK и 38 МиБ WASM.

Официальные ограничения: [экспорт Godot для Web](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html), [workflow GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
