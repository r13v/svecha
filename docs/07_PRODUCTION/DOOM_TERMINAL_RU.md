# Терминал помощи кошкам и скрытый Doom

Единственная целевая платформа — Web. Компактный настенный терминал находится внутри храма слева от входа, у боковой стены притвора. Он заменил прежний ноутбук на ящиках: устаревшая модель удалена из игры и экспорта.

## Поведение

- **E** приближает камеру к настоящему 3D-дисплею за 0,65 с; экран занимает около 83% высоты окна, в узком окне ограничивается шириной. Курсор освобождается для кликов.
- Главная страница предлагает помочь **PurrMačka**, волонтёрскому проекту помощи бездомным кошкам в Белграде. Кнопка открывает именно [https://purrmacka.org/ru/](https://purrmacka.org/ru/) в новой вкладке. Получатель и переход на внешний сайт указаны до клика. Платёжные данные игра не запрашивает, подтверждение оплаты не имитирует.
- **Одно касание** отклеившегося верхнего правого уголка вызывает короткое мерцание и открывает диагностику. Удержание не требуется. «Проверка экрана» показывает цветные полосы, «Проверка звука» воспроизводит короткий тон.
- Только **«Тест производительности · 1993»** запускает Doom E1M1 (shareware). До выбора этого пункта нет запросов движка Doom или WAD. Пожертвование не связано с доступом к секрету.
- В Doom: WASD — движение, мышь / стрелки — поворот, Ctrl / ЛКМ — огонь, E — двери, Esc — меню. **F10** или «Отойти от экрана» возвращает прежний вид за 0,55 с. На обычных страницах Esc возвращает главный экран, а с главного экрана позволяет отойти.
- Во время использования терминала остановлены основной мир, движение посетителя и расход всех свечей. Возвращение не начисляет пропущенное время.
- После выхода терминал снова показывает получателя пожертвования. Повторное открытие диагностики и теста продолжает тот же сеанс Doom. Новый основной эпизод или перезагрузка вкладки сбрасывает его; постоянного сохранения нет.
- Потеря фокуса останавливает Doom и звук. Ошибку загрузки можно повторить; из терминала можно выйти независимо от состояния Doom.

## Устройство

`game/scripts/donation_terminal.gd` управляет камерой, поверхностью дисплея, обычными страницами и сеансом Doom. Существующий луч в `church.gd` находит терминал. Модель — `donation_terminal.glb`, узел дисплея `ScreenAnchor`, размер 0,32 × 0,24 м.

Обычные страницы рисуются `terminal_display.gd` в SubViewport 800×600, его текстура показана на QuadMesh. Позиция мыши переводится лучом камеры на плоскость дисплея и в координаты этой же страницы; зоны клика и изображение совпадают при изменении размера окна. При запуске Doom материал переключается на ImageTexture 320×200 с пиксельным фильтром и историческим соотношением 4:3.

`game/web/doom_bridge.js` лениво создаёт невидимый локальный iframe с `doom/host.html`. Отдельный JavaScript-контекст изолирует два Emscripten runtime. Адаптер переводит палитру Doom в RGBA и копирует кадр в контекст основной страницы; JavaScriptBridge передаёт байты текстуре Godot. Ввод идёт обратно через небольшие C-функции; звук — SDL2/Web Audio. Сервер Doom и внешние запросы во время его игры не нужны.

При паузе останавливаются игровой цикл, AudioContext и часы Doom; нажатые кнопки отпускаются. Это исключает ускоренную симуляцию после возвращения.

В основе — [cloudflare/doom-wasm](https://github.com/cloudflare/doom-wasm), ревизия `65e0d3ae2ffa604155eebd96ed40da6567bd08f4`. Изменения адаптера собраны в `tools/build_doom.py` и `tools/doom/`: вывод кадров, ввод, пауза, завершение, программный OPL3 без блокирующего аппаратного опроса и единый исходный размер `boolean` для совместимости C-модулей. Остальная логика Doom остаётся upstream.

## Повторная сборка

Обычный `./tools/export_web.sh` использует готовые проверенные `game/web/doom/doom.js` и `doom.wasm`. Он копирует всю папку Doom рядом с экспортом. Ресурсы Doom лежат вне начального PCK и запрашиваются только при выборе скрытого теста.

Для изменения порта требуется **Emscripten 3.1.64**:

```sh
git clone https://github.com/emscripten-core/emsdk.git .tools/emsdk
.tools/emsdk/emsdk install 3.1.64
.tools/emsdk/emsdk activate 3.1.64
python3 tools/build_doom.py
./tools/export_web.sh
```

Можно передать другой путь к этому компилятору через `EMCC`. Сборщик проверяет версию и SHA-256 исходного архива, компилирует upstream-списки C-файлов, сохраняет лицензии, исходный архив, исходники адаптера и контрольные суммы в `manifest.json`. Emscripten при первой сборке загружает свои SDL-порты.

Модель повторяется командой:

```sh
./tools/blender --background --factory-startup --python-exit-code 1 --python tools/build_donation_terminal.py
./tools/godot --headless --editor --path game --import
```

## Проверки

`game/tests/check_donation_terminal.gd` проверяет обычный пеший маршрут, взаимодействие лучом, защиту от повторного входа, открытие секрета одним касанием, совпадение зон клика с 3D-дисплеем, диагностику, сокрытие секрета после выхода, изоляцию движения, сохранение топлива, приближение и точное восстановление камеры. Основной регрессионный маршрут — `game/tests/check_game.gd`.

Для графической проверки именно экспортированного PCK:

```sh
python3 tools/prepare_doom_review.py
python3 -m http.server 8793 --directory .tools/checks/doom/site
```

Открыть локальную страницу и нажать Enter. Внешний проверочный сценарий доведёт посетителя обычным маршрутом к терминалу; затем E, касание уголка, выбор теста, управление Doom и F10 выполняются через настоящий ввод браузера. Проверочный сценарий не включается в релизный PCK.
