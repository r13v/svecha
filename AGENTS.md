# Работа над «Свечой»

## Перед работой

Прочитай `README.md`, затем документы из `docs/`, относящиеся к текущей задаче. Концепция и рамки первой версии находятся в `docs/01_PROJECT_BRIEF/PROJECT_BRIEF_RU.md`, текущее состояние этапов — в `docs/07_PRODUCTION/STEP_BY_STEP_RU.md`.

## Основные правила

1. **Подумай перед кодом.** Явно называй предположения. Если неизвестное меняет задачу или дорогое решение, уточни его. Предлагай более простой подход, когда он решает задачу. Не продолжай в условиях непонимания.
2. **Простота.** Минимум кода для текущей задачи. Без спекулятивных систем и абстракций для одного использования.
3. **Точечные изменения.** Меняй только необходимое. Не улучшай соседний код и не рефактори работающее без причины.
4. **Проверяемый результат.** До реализации определи критерии успеха; работай до их проверки. Отличай запуск, автоматическую проверку и ручное прохождение.
5. **Конфликты обозначай.** Выбери более актуальное или лучше проверенное правило, объясни выбор. Не смешивай противоречивые подходы молча.
6. **Сначала чтение.** Перед изменением прочитай файл, вызывающий код, связанные сцены и общие функции. Неясную причину существующего решения уточняй.
7. **Тесты проверяют смысл.** Проверяй ограничения игрового действия и возможные сбои. Тест должен падать, если нарушается важное для игрока правило.
8. **Следуй соглашениям проекта.** Не создавай параллельный стиль. Проблемное соглашение сначала обозначь.

## Границы проекта

- Один компактный храм с подходом к входу. От первого лица, спокойный темп, одна свеча.
- Код будущей игры — `game/`, исходники Blender — `art/`, вспомогательные команды — `tools/`.
- `dust-horizon-template/` служит примером подхода. Не переносить его сюжет, боевые механики или требования к пустоши. Не менять его при разработке нашей игры.
- Сначала полный проходимый прототип, затем окончательные ассеты. В исходном шаблоне порядок неоднозначен; для нашего проекта действует порядок из `docs/07_PRODUCTION/STEP_BY_STEP_RU.md`.
- Не добавлять без задачи боевую систему, экономику, квестовый движок, сетевую игру, сложный инвентарь, VR или NPC.
- Не оценивать религиозное действие очками, не вводить обязательный текст молитвы или универсальные «правила посещения». Художественные детали конкретного храма требуют референсов.

## Код и сцены

- Проверенная локальная версия: Godot 4.7.2 stable, обычная сборка, GDScript. Изменение версии — отдельное решение.
- Имена файлов: `snake_case.gd`, `snake_case.tscn`; имена узлов: `PascalCase`; типизированный GDScript, отступы табуляцией.
- Использовать `CharacterBody3D`, физический цикл для движения и один луч взаимодействия. Для свечи достаточно явных состояний положения и горения плюс конечный запас горючего.
- Свечи расходуются в масштабе времени 1:1 и догорают до негорящего остатка; это относится и к окружению. Пауза останавливает симуляцию. По прямому решению пользователя полная новая свеча сгорает за 20 минут (1200 с) активного горения; для окружения действует тот же полный срок и свой начальный остаток. Не заменять расход бесконечным циклом или неизменяемыми декоративными свечами.
- Прямые ссылки и сигналы предпочтительнее глобального event bus. Autoload, DI, ECS и плагины вводить только при доказанной необходимости.
- `.gd`, `.tscn`, `.tres`, `.uid`, настройки импорта `.import` — исходные данные; `.godot/` — кэш. Не придумывать UID и не править кэш вручную.
- После изменения сцены/ассета выполнить импорт Godot. После изменения кода — проверку скрипта, ограниченный запуск и подходящую проверку поведения. Проверять журнал ошибок, а не только exit code.
- Headless-проверка не подтверждает качество графики, света, звука или удобство управления. Для них нужен запуск с изображением и проверка от лица игрока.

## Основные команды

- Выполнять из корня репозитория; список целей — `make help`. Makefile вызывает существующие команды `tools/`; общую логику сборки сохранять в этих скриптах.
- Разработка: `make run`, `make editor`, `make review-assets`. Пути к приложениям задаются через `GODOT_BIN` и `BLENDER_BIN`.
- После изменения ресурсов — `make import`. `make test` сам выполняет импорт, затем все `game/tests/check_*.gd` и тесты Web-упаковки. `make check` добавляет ограниченный headless-запуск на 120 кадров. Проверять вывод на ошибки даже при нулевом exit code.
- Целевая платформа — Web: `make export-web`, затем `make serve-web` (порт 8787, настройка `PORT=8080`). `make check-web-load` проверяет готовую сборку и журнал в браузере; `make check-web` дополнительно проверяет управление. Нужны `agent-browser` с Chromium, для управления — разблокированный рабочий стол. `make export-macos` остаётся вспомогательной локальной сборкой.
- Инструменты: `make setup`, `make check-pipeline`, `make blender-mcp`, `make check-blender-mcp`. Установка MCP не нужна для обычного запуска игры и Web-экспорта.
- При изменении набора целей синхронизировать справку Makefile, README и этот раздел.

## Навыки и Blender

- `.agents/skills/gdscript-patterns/` — GDScript; `.agents/skills/3d-essentials/` — визуальные системы Godot. Открывать только нужные references.
- `.agents/skills/blender-godot-assets/` — моделирование и экспорт для этого проекта. Для использования прочитать его `SKILL.md`.
- Навыки сообщества — подсказки, а не источник истины об API. Проверяй спорные утверждения по установленному движку и официальной документации. Перечни возможностей в навыках не означают, что их нужно внедрить.
- Blender MCP — интерактивные изменения и просмотр сцены. Blender CLI — повторяемое создание, экспорт и тяжёлые операции. Godot CLI — импорт и проверки; Godot MCP пока не установлен.
- Для материалов и масштаба результат в Godot важнее Blender-render. Сохраняй `.blend` и экспортируй отдельные `.glb`; игровую логику держи в `.tscn` поверх импортированной модели.
- Фиксируй авторов, лицензии и источники сторонних изображений, моделей и аудио в `docs/07_PRODUCTION/ASSET_SOURCES_RU.md` при первом их добавлении.
- Не перезаписывай чужую открытую Blender-сцену. Проектный запуск создаёт отдельное окно; изменения запрошенного ассета сохраняй в согласованный путь проекта.
- Не публикуй проект и не отправляй сообщения другим людям без явного запроса пользователя.
