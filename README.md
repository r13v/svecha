# Свеча

Короткая 3D-игра от первого лица: человек входит в православный храм, берёт свечу, зажигает её и ставит перед иконой. Рабочее название — «Свеча».

Цель первой версии — спокойный законченный эпизод на 3–5 минут. В центре внимания: пространство храма, звук шагов, движение руки и пламя. Все горящие свечи постепенно расходуются в реальном масштабе времени и в конце гаснут; ждать полного догорания для завершения эпизода не требуется.

**В версии 0.2.1 переработана графика по девяти концептам и исправлена рука.** 31 Blender-модель с GLB: резная столярка, оконные ниши, каменный пол, сланцевая кровля, убранство, двор и анатомическая кисть. Добавлены PBR-материалы, запечённый свет интерьера, правильное направление сгиба пальцев и плавный хват свечи. Сохранён полный эпизод: дверь, взятие, зажигание, установка, конечное горение, пауза и повтор.

[Исправление руки: кадры и видео](docs/04_BLENDER_ENV/fidelity/hands/README_RU.md) · [Сравнение девяти концептов с игрой](docs/04_BLENDER_ENV/fidelity/compare.html) · [Ассеты и воспроизведение](docs/04_BLENDER_ENV/ASSET_PIPELINE_RU.md)

**В локальный проект и macOS-сборку добавлена пасхалка — кот-смотритель.** Он спит снаружи на подоконнике первого окна справа от входа. Подойдите и задержитесь: кот приоткроет один глаз и снова уснёт. [Игровые кадры и проверка](docs/04_BLENDER_ENV/fidelity/cat/README_RU.md). Опубликованная веб-версия пока не обновлена.

**Запустить для разработки:** выполнить из корня `make run`. Кнопка «Войти в тишину» начинает эпизод. WASD — ходьба, мышь — обзор, E — действие, Esc — пауза и продолжение.

**[Играть в браузере](https://r13v.github.io/svecha/)** — для компьютера с клавиатурой и мышью. Первое открытие требует загрузки ресурсов. [Сборка, ограничения и GitHub Pages](docs/07_PRODUCTION/WEB_RU.md).

Все горящие свечи имеют конечный запас воска; пауза по Esc и потеря фокуса останавливают расход. По решению пользователя новая свеча полностью сгорает за **20 минут (1200 с) активного горения**. Уже горящие свечи окружения начинают с меньшим остатком. Ждать догорания для выхода не нужно.

**Единственная целевая платформа — Web**, компьютер с клавиатурой и мышью. Ранее созданная macOS-сборка остаётся историческим артефактом; нативный Godot используется для разработки и технических проверок.

**В локальной Web-версии есть терминал помощи кошкам.** Внутри храма слева от входа висит небольшой экран: E приближает камеру, кнопка «Помочь PurrMačka» открывает [сайт проекта](https://purrmacka.org/ru/) в новой вкладке. Одно касание отклеившегося верхнего правого уголка открывает диагностику, а «Тест производительности · 1993» запускает Doom. Esc — меню Doom, F10 — отойти; мир и свечи на паузе. [Устройство и проверка](docs/07_PRODUCTION/DOOM_TERMINAL_RU.md). Обновление не опубликовано.

## Проверка и сборка

Основные действия собраны в [Makefile](Makefile). Команды выполняются из корня репозитория; `make` или `make help` выводит справку. Нужны `make`, Godot **4.7.2 stable** и Python 3; для Web-сборки — шаблоны экспорта той же версии и `rsync`.

```sh
make editor       # Редактор Godot
make check        # Импорт, тесты и headless-запуск на 120 кадров
make export-web   # Сборка в builds/web и проверка бюджета размера
make serve-web    # http://127.0.0.1:8787; остановка — Ctrl+C
```

`make import` выполняет только импорт, `make test` — импорт, все проверки `game/tests/check_*.gd` (свечи, игровой маршрут, кот и терминал) и тесты Web-упаковки. При ошибке команды выполнение прекращается; журнал Godot также нужно проверять на ошибки. Headless-проверки не подтверждают качество изображения, звука и управления.

После экспорта `make check-web-load` проверяет загрузку WebGL и журнал браузера, а `make check-web` — также захват мыши, движение и паузу. Нужен установленный `agent-browser` 0.37.1 с Chromium; для управления — разблокированный рабочий стол. Сервер этих проверок использует порт 8788. `make serve-web PORT=8080` меняет порт сервера для ручного просмотра; сервер раздаёт уже готовую сборку.

[Результаты проверки и производительность](docs/07_PRODUCTION/VALIDATION_RU.md) · [Ассеты и игровые кадры](docs/04_BLENDER_ENV/ASSET_PIPELINE_RU.md). Отдельный просмотр высоты воска: `make review-assets`. Вспомогательная macOS-сборка: `make export-macos` (на Mac, с шаблоном macOS и `codesign`).

Остаётся художественная оценка пользователем. Публикация на GitHub Pages описана в [Web-документации](docs/07_PRODUCTION/WEB_RU.md).

## Быстрый старт инструментов

Команды выполняются из корня репозитория. Godot и Blender уже установлены на текущем Mac; запускать установку самих приложений повторно не нужно.

```sh
./tools/godot --version
./tools/blender --version
make setup
make check-pipeline
```

`make setup` требует `uv`, создаёт Python-окружение и локальную конфигурацию MCP. Для запуска игры и Web-экспорта эта настройка не требуется. Пути к приложениям можно переопределить: `make run GODOT_BIN=/path/to/godot`, `make blender-mcp BLENDER_BIN=/path/to/blender`.

Для интерактивной работы агента в отдельном окне Blender:

```sh
make blender-mcp
```

Проверка соединения из другого терминала:

```sh
make check-blender-mcp
```

Навыки хранятся в `.agents/skills/` и входят в репозиторий. Локальная конфигурация MCP создаётся в `.codex/config.toml`; зависимости и результаты технических проверок — в игнорируемой `.tools/`. Подробности и ограничения проверок — в [tooling.md](docs/07_PRODUCTION/TOOLING_RU.md).
